# لقمه — Sharif FoodBot

نسخهٔ اولیهٔ یک انتخاب‌گر شخصی غذای دانشگاه صنعتی شریف. لقمه از مقایسه‌های دوتایی یاد می‌گیرد، قوانین قطعی کاربر را اعمال می‌کند و برای هر روز یک انتخاب اصلی و چند جایگزین می‌سازد.

> این نسخه هیچ رزروی ثبت نمی‌کند و رمز سامانهٔ دانشگاه را در مرورگر، کد یا Git نگه نمی‌دارد.

## امکانات فعلی

- رابط فارسی و RTL برای برنامهٔ هفتگی
- مقایسهٔ دوتایی غذاها با ثبت دلیل انتخاب
- رتبه‌بندی سریع و قطعی بدون وابستگی به مدل زبانی در لحظهٔ تصمیم
- سقف قیمت، محدودیت فست‌فود و fallback به غذای سلف
- ذخیرهٔ محلی پروفایل و خروجی/ورودی JSON بدون credential
- ابزار مشاهدهٔ محلی سماد با پروفایل جدا و لاگ شبکهٔ ناشناس‌شده
- طراحی responsive و قابل استفاده با صفحه‌کلید

## اجرای وب‌اپ

```bash
npm install
npm run dev
```

سپس `http://localhost:3000` را باز کنید.

## مشاهدهٔ امن سامانهٔ سماد

```bash
npm run inspect:site
```

Chrome با پروفایل محلی `.runtime/browser-profile/` باز می‌شود. ورود را خود کاربر انجام می‌دهد. ابزار فقط method، path، status و نوع resource را در `.runtime/network.ndjson` نگه می‌دارد؛ header، cookie، query string و محتوای فرم ذخیره نمی‌شوند. مسیر `.runtime/` در Git نادیده گرفته شده است.

در حالت عادی، درخواست‌هایی که نامشان شبیه عملیات رزرو باشد مسدود می‌شوند. این ابزار برای شناخت جریان login/menu و کشف endpointها است، نه رزرو واقعی.

## معماری مرحله‌ای

```text
Web UI (فعلی)
  ├── pairwise preference profile
  ├── deterministic ranking
  └── hard safety rules

Observer (مرحلهٔ بعد)
  ├── خواندن منوی واقعی سماد
  ├── کشف زمان بازشدن
  └── ثبت لاگ بدون اطلاعات حساس

Reservation worker (پس از کالیبراسیون)
  ├── credential vault رمزنگاری‌شده
  ├── قفل و idempotency برای هر کاربر
  ├── retry محدود + fallback
  └── تأیید نتیجه و توقف فوری
```

GitHub Pages یا یک سایت static فقط برای UI مناسب است. Worker رزرو باید روی یک سرویس همیشه‌روشن با HTTPS و secret storage اجرا شود. برای رزرو رقابتی، GitHub Actions scheduler اصلی مناسبی نیست.

## گام‌های بعدی

1. اجرای `inspect:site` و ورود دستی به نسخهٔ قدیمی سماد
2. ثبت یک نشست فقط‌خواندنی و ناشناس‌سازی fixtureهای HTML
3. ساخت parser منوی واقعی و اتصال آن به رتبه‌بندی فعلی
4. یک هفته اجرای observer برای تخمین زمان بازشدن
5. تست کنترل‌شدهٔ یک رزرو با idempotency و سقف درخواست
6. افزودن backend چندکاربره و credential vault روی VPS

## حریم خصوصی

فایل‌های `.env*`، `.runtime/`، `playwright/.auth/`، `*.har` و `*.ndjson` وارد Git نمی‌شوند. credential دانشگاه را هرگز در issue، commit، screenshot یا فایل profile قرار ندهید.
